# Data Explained

**Real-world data problems, solved in code and explained in plain English.**

Every case file starts with a question a real person in a real organisation would ask, such as *"Is A&E demand rising, or is it just Monday?"*, and works through it end to end:

| Section | What it gives you |
|---|---|
| 1. The problem | The business question, in words anyone can follow |
| 2. The data | Schema, where it comes from, and where to find the real thing |
| 3. The approach + code | Runnable SQL / Python, with the reasoning |
| 4. What we found | Results from the actual run, and the decision they drive |
| 5. Explain it twice | One version for a manager, one for a technical interviewer |
| 6. When to use it / gotchas | When the technique works, when it doesn't, and the mistakes people make |
| 7. Interview drill | Three questions you'll likely be asked, with crisp answers |

The goal is to show I can do the analysis **and** explain it to anyone, technical or not, across many industries.

**Skill lanes:** SQL + analytics · Stats + ML · Data engineering · AI / LLM / RAG
**Domains:** NHS / health · retail · banking · transport · energy · public sector · HR · subscriptions

## Run any case file

```bash
pip install -r requirements.txt
python posts/<case-file-folder>/analysis.py
```

Every script runs offline in under a minute with no API keys. Every pull request is checked by CI before it's merged.

## A note on the data

Organisations named here (Northshire NHS Trust, Harbour & Hale, and so on) are fictional. Datasets are **synthetic**: generated in code with a fixed seed, modelled on patterns in real public data, so every result is reproducible. Each case file points to a real public dataset you can try the same technique on.
